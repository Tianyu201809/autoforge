# Autoforge v1.27.0 版本说明

> 发布日期：2026-08-13 · 应用版本 `1.27.0` · 脚本清单规范 `autoforge 1.0`

Autoforge v1.27.0 新增原生可执行程序包支持。除 JavaScript 与 Python 脚本外，现在还可以导入并托管 Windows PE、macOS Mach-O 和 Linux ELF 主程序；平台负责识别入口、复制完整程序目录、请求运行授权、传递环境变量与参数，并管理日志、停止、超时和执行历史。

完整功能基线见 [v1.9.0](./v1.9.0.md)，上一版本变更见 [v1.26.0](./v1.26.0.md)。本文件仅描述 v1.27.0 新增与修复。

设计规格：[原生可执行程序支持](./superpowers/specs/2026-08-12-native-executable-support-design.md)。开发者契约见 [脚本包规范](./script-spec.md#原生可执行程序)。

---

## 相对 v1.26.0 的变化

| 领域 | 变更 |
|------|------|
| **脚本类型** | 新增 `language: "executable"`，与 `javascript`、`python` 一同持久化和展示 |
| **格式识别** | 按文件头识别 Windows PE、macOS Mach-O 与 Linux ELF 主程序，并排除 DLL、动态库、符号链接和其他非主程序文件 |
| **本地导入** | 支持有清单程序包，以及无清单的单文件、目录和 ZIP；唯一候选自动选中，多个候选由用户选择 |
| **安全授权** | 首次运行按脚本 ID、入口路径和 SHA-256 请求信任；入口内容变化后必须重新确认 |
| **执行托管** | 原生子进程使用脚本目录作为工作目录，采集 stdout/stderr，记录 PID 与退出码，并支持停止、超时和进程树清理 |
| **输入传递** | 清单 `env` 直接注入环境变量，`params` 通过规范化变量及 `AUTOFORGE_PARAMS_JSON` 传入 |
| **界面** | 增加 EXE 语言标识、多个入口选择窗口和原生程序专用配置分支；原生程序包暂不支持从 Autoforge 导出 ZIP |
| **Windows GUI 修复** | 不再隐藏通过 Autoforge 启动的 GUI 程序主窗口，修复 Electron 等应用进程存在但界面不显示、会话持续为 `running` 的问题 |

## 支持的原生程序

Autoforge 读取有限的二进制文件头判断格式，不依赖扩展名：

| 当前系统 | 支持的入口 | 排除项 |
|----------|------------|--------|
| Windows | PE 主程序，通常为 `.exe` | PE DLL |
| macOS | 32/64 位及 Fat Mach-O 主程序 | Mach-O 动态库；`.app` 应用包目录 |
| Linux | ELF 可执行文件，包括带解释器的动态可执行文件 | ELF 共享库 |

入口的目标操作系统必须与当前系统一致。识别结果会保留架构信息，但 v1.27.0 不在启动前阻止 CPU 架构不兼容的程序，此类错误由操作系统报告。

符号链接不会作为候选入口，也不会在本地目录导入时被跟随。扫描会跳过 `.git`、`.svn`、`.venv`、`.cache`、`__pycache__`、`node_modules` 和 `release` 等目录，单次最多检查 2,000 个文件系统条目。

## 清单与导入

### 显式清单

原生程序可以随包提供标准 `autoforge.json`：

```json
{
  "autoforge": "1.0",
  "name": "本地工具",
  "version": "1.0.0",
  "entry": "bin/tool.exe",
  "language": "executable",
  "env": [],
  "params": []
}
```

`entry` 必须位于包根内、是普通文件、不是符号链接，并且是当前系统可运行的 PE、Mach-O 或 ELF 主程序。原生程序不得声明 `dependencies`；Autoforge 不安装 DLL、共享库、系统运行库或其他原生依赖。

### 无清单本地导入

本地导入支持原生单文件、目录和 ZIP，即使来源中没有 `autoforge.json`：

1. Autoforge 扫描当前系统可运行的主程序候选。
2. 只有一个候选时自动选中；存在多个候选时显示相对路径、格式和大小供用户单选。
3. 选定后复制完整包目录到 Autoforge 工作区，再生成最小 `autoforge.json`。
4. 没有候选或用户取消选择时不创建脚本记录，并清理临时文件。

自动生成的清单使用入口文件名作为 `name`，版本为 `1.0.0`，并包含空的 `env` 与 `params`。

> Hub「添加到本地」在 v1.27.0 仍要求 ZIP 根目录或唯一一层子目录内存在 `autoforge.json`。Hub 不会为无清单原生 ZIP 自动选择入口。

## 运行授权

原生程序以当前用户权限访问本机文件和网络。首次从 Autoforge 界面运行前，主进程会显示程序名、入口相对路径、来源和完整 SHA-256，只有用户选择“信任并运行”后才启动。

- 信任记录绑定脚本 ID、入口相对路径与 SHA-256。
- 入口字节发生变化后，原信任自动失效并要求重新确认。
- 确认期间文件发生变化时，本次授权失败，不保存信任。
- 定时任务、批量运行和 MCP 属于非交互调用，不能授予新信任；必须先在 Autoforge 中手动确认一次当前版本的入口。
- 删除脚本时一并删除该脚本的信任记录。

授权只确认用户接受运行当前二进制文件，不提供沙箱或权限降级。

## 运行模型

原生入口直接作为子进程启动，不经过 shell：

```text
queued -> validating -> awaiting-confirmation -> starting -> running
                                                        |-> completed
                                                        |-> failed
                                                        `-> stopped
```

- 工作目录为导入后的脚本包根目录，程序可以按相对路径读取同目录资源。
- stdout 按 INFO、stderr 按 ERROR 写入现有实时日志。
- 退出码 `0` 对应成功；非零退出码对应失败并写入执行历史。
- GUI 程序在窗口保持打开期间会话保持 `running`，程序退出后才进入终态。
- 停止或超时会终止入口进程及其子进程树。
- macOS/Linux 会在授权后为入口补充当前用户执行位。
- Windows 启动参数保留 GUI 窗口可见性，Electron 等桌面程序可正常显示主窗口。

### 环境变量与参数

清单 `env` 的解析结果按原键名注入子进程。`params` 同时通过以下方式传入：

| 变量 | 内容 |
|------|------|
| `AUTOFORGE_PARAM_<NORMALIZED_KEY>` | 单个参数值；键转为大写，非 ASCII 字母和数字替换为 `_` |
| `AUTOFORGE_PARAMS_JSON` | 保留原始参数键名的完整 JSON 对象 |
| `AUTOFORGE_SESSION_ID` | 当前会话 ID |
| `AUTOFORGE_SCRIPT_ID` | 当前脚本 ID |
| `AUTOFORGE_SCRIPT_DIR` | 当前脚本包根目录 |

若两个参数键规范化后相同，例如 `order-id` 与 `order_id`，清单校验会拒绝该配置。

## 界面与限制

- 脚本卡片和详情页使用 `EXE` 标识原生程序。
- 原生入口是二进制文件，不提供应用内代码编辑。
- 原生程序不使用 JavaScript/Python 的 `run(ctx)`、浏览器 SDK、结构化结果或依赖安装协议。
- Autoforge v1.27.0 暂不支持导出原生程序 ZIP；界面禁用导出，主进程也会拒绝直接调用。
- 每个程序包只有一个字符串 `entry`，不支持在同一清单内配置多平台入口映射。
