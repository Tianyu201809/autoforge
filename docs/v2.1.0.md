# Autoforge v2.1.0 版本说明

> 发布日期：2026-11-24 · 应用版本 `2.1.0` · 脚本包规范 `autoforge 1.0`

v2.1.0 完善 AI 项目工作区的会话、素材和脚本导入流程。Agent 创建或修改文件时会默认遵循 Autoforge 脚本开发规范；构建和导入由用户显式触发，并使用确定性的本机校验流程。

## AI 项目工作区

- 工作区导航与交互进一步贴近 Codex 项目工作区；项目对话在切换页面时保留运行状态，返回后可继续查看和操作。
- 对话支持图片及文本、Markdown、JSON、代码和日志附件。Agent 的 Markdown 回复以富文本方式展示。
- 项目操作菜单支持在系统文件管理器中打开项目目录，也支持用设置中配置的 IDE 打开。
- Agent 每次请求都会默认收到 Autoforge 脚本开发规范，涵盖清单、语言入口、运行上下文、环境与运行参数、依赖、资源释放、安全和导出约定。

## 构建与导入

日常对话只通过受限文件工具创建和修改项目文件，不会自动运行构建、检查或导入。

用户点击“导入脚本”后，Autoforge 按以下顺序处理：

1. 项目存在 `package.json` 的 `scripts.build` 时执行 `npm run build`；没有构建脚本时直接处理现有入口。
2. 校验 `autoforge.json` 清单、项目入口和 JavaScript / Python 语法。
3. 校验通过后，将脚本导入注册表，或更新已关联的脚本。

该流程不调用 AI，也不会执行脚本入口。构建或检查失败时会显示具体错误并停止导入；用户修复项目后可以再次手动导入。

## 兼容性与安全

- 脚本包清单格式维持 `autoforge.json` 的 `"autoforge": "1.0"`，现有脚本包无需迁移。
- Agent 仍只能访问项目目录内受限的普通文本文件，不提供任意 shell 或脚本执行能力。
- 密钥和真实环境值不得写入生成文件；通过 Autoforge 的环境配置供脚本运行时读取。
- 项目文件保存在用户选择的本机目录中；移除工作区项目记录不会删除该目录。
