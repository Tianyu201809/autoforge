# Autoforge v2.0.0

2026-11-22

Autoforge 2.0 introduces a local AI project workspace and a project-first main window. Users select a local folder, choose JavaScript or Python and a model profile, then describe the script they want the Agent to create or change.

## AI project workflow

- Project metadata and conversation turns are stored in the Autoforge SQLite database. Project files remain in the selected local folder.
- The Agent reads and writes ordinary text files through bounded main-process tools. It cannot execute shell commands, install packages, or run generated scripts.
- File writes use expected SHA-256 values so edits made outside Autoforge are detected as conflicts.
- Autoforge validates the script package and checks JavaScript or Python syntax with fixed checkers. Passing both checks automatically imports or updates the script.
- Import does not run the generated script. The user starts it from the normal script workflow.
- Removing a project removes its Autoforge metadata and conversation, but leaves the selected folder and its files on disk.
- Project entries can be renamed, pinned, and exported as a JSON conversation archive. Removing a project requires two confirmations.

## Model providers

Model profiles support OpenAI, Anthropic, Gemini, and OpenAI-compatible services. Compatible presets include OpenAI, DeepSeek, Qwen, GLM, Kimi, and SiliconFlow, with editable endpoint and model fields.

API keys and extra header values are stored by the main process with Electron safeStorage when available. The renderer can save or clear credentials and see whether a key exists, but cannot read a saved key back. Connection test errors are normalized before they reach the UI.

## Unified workbench

The main window now uses a persistent navigation rail and adjustable workspace layout for Projects, Scripts, History, Autoforge Hub, Guide, and Settings. Project conversations include a file-change and check inspector. Existing script filtering, detail panels, execution logs, editor and terminal popouts, tray behavior, and drag-and-drop import remain available.

Navigation state stores the last view, active project and script, collapsed panels, and panel widths in local storage.

## Data and compatibility

Database migration 7 adds AI project and conversation tables. Existing script packages, script records, and execution history keep their current formats. Generated scripts use the existing autoforge.json package contract.

## Verification

The release workflow uses npm run test:unit, npm run lint, and npm run build. Generated code checks validate package structure and syntax without invoking the script entry point.
