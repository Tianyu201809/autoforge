# v1.31.0 版本说明

发布日期：2026-08-17

v1.31.0 补齐了原生可执行脚本的最后一块分发能力。自 v1.27.0 起 Autoforge 可以导入并托管运行 Windows PE、macOS Mach-O 和 Linux ELF 程序，但这类脚本无法导出，只能单向进入 Autoforge。现在原生程序包可以按整个目录导出为 ZIP，并重新导入到其他机器或发布到 AutoforgeHub。

## 主要更新

### 原生脚本导出 ZIP

`language: "executable"` 的脚本卡片重新启用“导出 ZIP”，与 JavaScript / Python 脚本共用同一套预览、确认和保存流程。

原生程序包采用**整目录打包**：导出器不读取也不解析二进制内容，直接把整个脚本工作区按原有目录结构写入 ZIP。因此 DLL、动态库、配置、数据和子目录资源都会自动带上，用户不需要在清单里逐项声明，也不需要关心 Autoforge 能否识别某种文件类型。

`export.include` 对原生包不再有作用。已经声明该字段的清单可以原样保留，导出时会被忽略且不报错。

### 排除范围

原生包只排除下列内容，其余文件一律打包：

| 排除项 | 范围 |
|--------|------|
| 依赖与缓存目录 | `node_modules`、`.venv`、`venv`、`site-packages`、`.git`、`.svn`、`__pycache__`、`.pytest_cache`、`.mypy_cache` |
| Autoforge 内部文件 | `.autoforge-attachments/`、`.autoforge-output/`、`.autoforge-deps.json` |
| 环境变量文件 | `.env` 及 `.env.*` |
| 凭据文件 | `.pem`、`.key`、`.p12`、`.pfx`、`.crt`、`.cer` |
| 符号链接 | 工作区内任意位置出现符号链接时导出被拒绝 |

JavaScript / Python 导出会排除的 `.json` 配置、数据库、表格、日志、内嵌压缩包以及 `dist/`、`release/` 等目录，对原生包都属于程序自身内容，会正常导出。

### 容量上限提升到 500 MB

原生程序体积远大于脚本源码，导出上限相应放宽：

| 限制 | v1.30.0 及以前 | v1.31.0 |
|------|----------------|---------|
| 单个文件 | 10 MB | 500 MB |
| 全部文件合计 | 50 MB | 500 MB |

两个上限都按纳入文件的**未压缩**大小计算，不以 ZIP 压缩后的实际体积为依据。超限时导出被拒绝并给出具体文件路径。

## 使用流程

1. 在脚本卡片菜单选择“导出 ZIP”。
2. 预览弹窗显示将打包的文件数量和总大小，并列出被排除的内容。
3. 确认后选择保存位置，Autoforge 写出 ZIP 并提示文件名与文件数。
4. 该 ZIP 可通过本地导入或 Hub 分发重新安装；重新导入后首次运行仍需按 SHA-256 重新授权。

## 安全边界

整目录打包只放宽了文件类型限制，路径与凭据相关的约束都保留：

- 所有文件仍须通过路径规范化、工作区边界、普通文件校验，不会越出脚本工作区。
- 工作区内任意位置出现符号链接时导出被拒绝，不会跟随链接打包目标文件。
- `.env` 系列、`.pem`、`.key`、`.p12`、`.pfx`、`.crt`、`.cer` 以及依赖与缓存目录始终被排除。
- 入口位于被排除目录（例如 `node_modules/tool.exe`）时导出被拒绝。
- 导出计划与实际写盘使用同一套语言相关校验，预览结果与落盘内容一致。
- 导出不授予任何运行权限。原生程序的 SHA-256 信任记录不随 ZIP 分发，目标机器首次运行必须重新确认。

> [!IMPORTANT]
> 整目录打包意味着脚本工作区内的业务数据也会进入 ZIP。分发前请确认目录中没有不应外发的运行产物、导出结果或数据文件。

## 兼容性

- JavaScript 与 Python 的静态依赖分析、`export.include` 语义和导出结果没有变化。
- 已有清单无需修改；原生包中已声明的 `export.include` 会被忽略且不报错。
- JavaScript / Python 包的入口仍不接受二进制文件，放宽的文件类型规则只对 `executable` 生效。
