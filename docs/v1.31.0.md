# v1.31.0 版本说明

发布日期：2026-08-17

v1.31.0 补齐了原生可执行脚本的最后一块分发能力。自 v1.27.0 起 Autoforge 可以导入并托管运行 Windows PE、macOS Mach-O 和 Linux ELF 程序，但这类脚本无法导出，只能单向进入 Autoforge。现在原生程序包可以导出为 ZIP，并重新导入到其他机器或发布到 AutoforgeHub。

## 主要更新

### 原生脚本导出 ZIP

`language: "executable"` 的脚本卡片重新启用“导出 ZIP”，与 JavaScript / Python 脚本共用同一套预览、确认和保存流程。

导出的 ZIP 固定包含：

- `autoforge.json` 清单。
- 清单 `entry` 声明的入口程序。
- 包根的 `README.md` 或 `README`（存在时）。
- `export.include` 匹配到的全部文件。

导出器不读取也不解析二进制内容，因此不会自动发现 PE、Mach-O 或 ELF 的动态库依赖。

### 运行资源需要显式声明

原生程序在运行时动态加载的资源必须写进清单的 `export.include`，否则不会进入 ZIP：

```json
{
  "autoforge": "1.0",
  "name": "本地工具",
  "entry": "bin/tool.exe",
  "language": "executable",
  "export": {
    "include": ["bin/*.dll", "bin/settings.ini", "assets/**/*"]
  }
}
```

导出白名单已扩展到二进制入口和原生包常见的运行资源，包括：

| 类别 | 覆盖范围 |
|------|----------|
| 入口程序 | `.exe`、`.com`、`.bin`，以及 macOS / Linux 上无扩展名的入口 |
| 动态库 | `.dll`、`.so`、`.dylib`、`.node`、`.pyd`，含 `libfoo.so.1.2` 这类版本化共享库 |
| 配置 | `.ini`、`.cfg`、`.conf`、`.properties`、`.toml`、`.yaml`、`.yml`、`.xml`、`.manifest` |
| 资源 | `.dat`、`.pak`、`.res`、字体、图标、图片与音频 |

### 容量上限提升到 500 MB

原生程序体积远大于脚本源码，导出上限相应放宽：

| 限制 | v1.30.0 及以前 | v1.31.0 |
|------|----------------|---------|
| 单个文件 | 10 MB | 500 MB |
| 全部文件合计 | 50 MB | 500 MB |

两个上限都按纳入文件的**未压缩**大小计算，不以 ZIP 压缩后的实际体积为依据。超限时导出被拒绝并给出具体文件路径。

## 使用流程

1. 在脚本卡片菜单选择“导出 ZIP”。
2. 查看预览弹窗中的文件数量和总大小，确认动态加载的资源已在 `export.include` 中声明。
3. 确认后选择保存位置，Autoforge 写出 ZIP 并提示文件名与文件数。
4. 该 ZIP 可通过本地导入或 Hub 分发重新安装；重新导入后首次运行仍需按 SHA-256 重新授权。

## 安全边界

原生分支不放宽任何既有导出限制：

- 所有文件仍须通过路径规范化、工作区边界、普通文件和非符号链接校验。
- 密钥、证书、数据库、表格、日志、压缩包和 `.env` 系列文件继续被强制排除。
- `node_modules`、`.venv`、`.git`、缓存目录和 `dist`、`release` 等构建产物目录继续被排除。
- `export.include` 无法绕过上述规则；未匹配到文件、匹配到受限文件或匹配到越界路径时导出被拒绝。
- 导出计划与实际写盘使用同一套语言白名单校验，预览结果与落盘内容一致。
- 导出不授予任何运行权限。原生程序的 SHA-256 信任记录不随 ZIP 分发，目标机器首次运行必须重新确认。

## 兼容性

- JavaScript 与 Python 的静态依赖分析、`export.include` 语义和导出结果没有变化。
- 已有清单无需修改；只有需要携带额外运行资源的原生包才需要补充 `export.include`。
- JavaScript / Python 包的入口仍不接受二进制文件，扩展的白名单只对 `executable` 生效。
