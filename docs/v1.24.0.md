# Autoforge v1.24.0 版本说明

> 发布日期：2026-08-06 · 应用版本 `1.24.0` · 脚本规范 `autoforge 1.0`

Autoforge 是本机自动化脚本锻造与管理桌面应用。v1.24.0 新增 **本地 MCP 控制面**：Codex、Claude、Cursor 等 Agent 可在用户明确开启后，通过标准 MCP 查询、编辑和运行 Autoforge 脚本。

完整功能基线见 [v1.9.0](./v1.9.0.md)；近期分类树与多实例批量见 [v1.20.0](./v1.20.0.md)。本文档仅描述 v1.24.0 新增与变更。

设计规格：[2026-08-05-mcp-integration-design.md](./superpowers/specs/2026-08-05-mcp-integration-design.md)

---

## 相对 v1.23.1 的变化

| 领域 | 变更 |
|------|------|
| **MCP 控制面** | 新增标准 stdio adapter、本地主进程控制服务和共享领域 Facade；MCP 默认关闭，由设置页控制 |
| **Agent 接入** | 设置页提供 Codex TOML、Codex CLI 安装命令和 Claude / Cursor 通用 JSON；命令与参数严格分离 |
| **工具与资源** | 覆盖脚本、文件、环境、运行 session、日志和执行历史；写操作要求 `confirm: true` |
| **本机安全** | Windows Named Pipe / macOS、Linux Unix Socket；运行时 token 自动发现与轮换；secret 脱敏；JSONL 审计 |
| **连接稳定性** | adapter 支持 Autoforge 后启动、应用重启和 token 轮换后的按需重连 |
| **Codex 兼容** | 数组结果封装为对象 `structuredContent`；修复错误参数导致重复启动 Autoforge 窗口的问题 |

## MCP 架构

### 进程边界

```text
Codex / Claude / Cursor
    │ 标准 MCP stdio
    ▼
Autoforge MCP adapter（轻量子进程，不创建窗口）
    │ Windows Named Pipe / macOS、Linux Unix Socket
    ▼
Autoforge 主进程 McpControlServer
    │
    ├── AutoforgeControlFacade
    ├── RunEventStore
    └── McpAuditService
```

adapter 只负责 MCP 协议、工具 / resource 注册、本地握手和断线恢复，不直接读取 SQLite、不创建第二套 Runner，也不会自动启动 Autoforge 桌面程序。主进程通过共享 Facade 复用现有脚本、环境、运行与历史服务，保证 UI 和 Agent 使用相同的业务校验。

### 模块

| 模块 | 职责 |
|------|------|
| `mcp/stdio-server` | 标准 MCP stdio 生命周期与 adapter 入口 |
| `mcp/tool-definitions` | 工具 schema、结果封装和错误转换 |
| `mcp/resource-definitions` | 只读 resource URI 与内容 |
| `mcp/control-client` | descriptor 发现、握手、请求匹配和自动重连 |
| `mcp-control-server` | 本地 socket、认证、路由、连接和并发限制 |
| `autoforge-control-facade` | IPC / MCP 共用的领域操作 |
| `run-event-store` | session 快照、增量日志和终态等待 |
| `mcp-audit` | 不含参数值和 secret 的 JSONL 审计 |

## 开启与客户端接入

### Autoforge 设置

1. 打开 **设置 → MCP**。
2. 开启“允许本地 MCP 控制”，并保持 Autoforge 在后台运行。
3. 选择 **Codex** 或 **Claude / Cursor**，复制对应配置。
4. 新建 Agent 会话，让客户端重新加载 MCP adapter。

设置页显示服务状态、运行环境、transport、endpoint、连接数和最近连接时间，并支持轮换安全令牌。Autoforge 不会自动修改第三方客户端配置。

### Codex

Codex App、CLI 和 IDE 扩展使用 `config.toml`。设置页可复制完整 TOML，也可复制一次性的 `codex mcp add` 命令。

开发环境生成的结构为：

```toml
[mcp_servers.autoforge]
command = "npm.cmd"
args = ["--prefix", "C:\\personal\\autoforge", "run", "mcp", "--", "--app-env", "development"]
startup_timeout_sec = 30
```

`command` 必须只包含可执行文件，每个 `args` 项必须是独立参数。不能把 `npm run mcp` 或 `--app-env development` 合并成一个值；错误边界会使 Electron 无法识别 stdio 模式，并可能重复打开 Autoforge 窗口。

### Claude / Cursor

使用客户端支持的 `mcpServers` JSON。生产安装包通过 Autoforge 可执行文件加 `--mcp-stdio --app-env production` 启动 adapter；开发环境使用设置页生成的 `npm.cmd --prefix ...` 参数数组。

用户不需要另外安装 MCP client，也不需要在 Agent 配置中填写 Autoforge token。源码开发环境仍需先安装项目依赖。

## 工具与 Resources

### 工具范围

| 分组 | 能力 |
|------|------|
| **查询** | 脚本列表与详情、工作区文件、环境 Profile、当前 session、增量日志、执行历史 |
| **运行** | 启动脚本、停止单个 session、停止脚本全部 session、等待终态 |
| **脚本写入** | 创建、导入、修改文件与元数据、删除脚本 |
| **环境写入** | 创建、更新、删除 Profile；保存脚本 env / params |

脚本与环境写操作必须显式传入 `confirm: true`。`autoforge_start_script` 默认不持久化参数；仅当 `persistParams: true` 时要求确认。启动成功会立即返回 session，Agent 可继续查询状态、读取日志或等待终态。

### 只读 Resources

- `autoforge://app/status`
- `autoforge://scripts`
- `autoforge://scripts/{scriptId}/manifest`
- `autoforge://sessions/{sessionId}`
- `autoforge://sessions/{sessionId}/logs`

工具和 resource 使用相同的 JSON-safe DTO 与 secret 脱敏规则。

## Token 与安全边界

- MCP 默认关闭，只监听本机 Named Pipe / Unix Socket，不新增 TCP 端口。
- 主进程每次启用或轮换时生成 32 字节 token，写入当前用户的 runtime descriptor。
- adapter 自动发现 descriptor 并握手；token 不进入 renderer、复制配置、工具结果、日志或审计记录。
- 关闭 MCP 会断开已有连接并删除 descriptor；轮换 token 会使旧连接立即失效。
- env / params schema 中的 secret 只返回存在性或掩码，不回显原值。
- 文件访问限制在脚本工作区内，拒绝绝对路径、路径穿越和 symlink 越界。
- 审计记录仅包含时间、连接、操作、目标、确认状态、结果和错误码，不记录文件内容或参数值。

该 token 用于同一用户下的本机误连防护，不等同于操作系统级沙箱。Codex 自身的账号或 API 认证仍由 Codex 管理，与 Autoforge runtime token 无关。

## 连接与兼容性修复

### adapter 自动重连

Codex 的 stdio 模式会为每个 Agent 会话启动一个轻量 adapter 子进程，这是正常行为。v1.24.0 保存 descriptor discovery 参数，并在每次工具请求前核对 PID、endpoint 和 token：

- adapter 先启动、Autoforge 后启动时，下一次调用会自动建立连接；
- Autoforge 重启后，adapter 会发现新 descriptor 并重新握手；
- token 轮换后，旧 socket 不会继续使用过期凭据；
- 旧 socket 的延迟 `close` 事件不会清空新连接。

Autoforge 未运行或 MCP 关闭时，adapter 仍可完成标准 MCP 初始化，但控制工具会返回可重试的 `app_not_ready`。

### Codex structuredContent

MCP 要求 `structuredContent` 为对象。环境列表、session 列表等数组结果统一封装为：

```json
{
  "value": []
}
```

文本结果与结构化结果保持一致，避免 Codex 因收到顶层数组而拒绝工具结果。

## 本期不包含

v1.24.0 不提供以下 Agent 能力：

- MCP Prompts；
- npm / pip 依赖安装；
- 分类管理；
- 调度与 Cron 管理；
- Autoforge 窗口控制；
- 任意 shell 执行。

这些能力需要单独评估权限、确认流程和审计边界，不会复用当前脚本控制权限隐式开放。
