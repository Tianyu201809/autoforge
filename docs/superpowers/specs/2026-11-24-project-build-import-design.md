# 项目编辑器入口与构建导入

状态：按用户最新要求调整为直接构建导入，不接入 AI。

## 范围与方案

项目列表右键菜单和现有省略号菜单共用操作项，新增“使用编辑器打开”。传入被操作项目的 rootPath，复用应用现有 IDE 配置、选择器和 IPC，不以当前选中项目代替右键目标。菜单另有“打开文件目录”，使用系统文件管理器打开该项目目录。

用户点击“导入脚本”，应用直接运行 package.json 的 scripts.build（存在时），然后校验 autoforge.json 的入口和语言语法，全部通过才导入 Autoforge。构建失败提供诊断并停止，用户处理后手动重试；不调用模型、不自动修复。无 build 脚本的 JavaScript/Python 项目直接检查导入。不自动安装依赖，不改变普通对话的导入边界。

选择固定的 npm run build 约定，避免另设一套构建配置。直接导入源码无法覆盖入口由构建生成的项目；允许模型自行执行任意命令则超出当前工具职责。

按最新两张截图删除主导航品牌行、脚本上下文侧栏底部的四个重复快捷入口。主导航保留原有功能入口。

## 实现与验证

- 构建器限制诊断输出，默认两分钟超时；取消或超时终止构建进程树。
- 独立导入流程先构建再执行包、语法检查；与聊天共享项目锁和取消机制，不读取模型配置或凭据。
- 使用真实 npm 构建 fixture 验证中文路径、失败、取消、超时，验证 dist 入口生成后通过检查并实际导入。
- 浏览器验证右键未选中项目时打开正确目录，保持原项目会话；继续覆盖 Markdown、素材与运行期间切页回归。
- 浏览器夹具共享 Vite 优化缓存，因此测试文件串行运行，避免不同配置同时重写缓存。

## 影响与边界

仅影响 autoforge：AI 项目服务、项目操作菜单及导航展示。复用现有脚本注册表更新规则与 IDE/文件管理器 IPC；导入入口统一为 importProject / AI_PROJECT_IMPORT。构建依赖由用户项目自行准备；目录中的符号链接仍按现有包安全规则处理。
