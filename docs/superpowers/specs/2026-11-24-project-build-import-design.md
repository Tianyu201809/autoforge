# 项目编辑器入口与构建导入

状态：按用户确认的构建约定实施。

## 范围与方案

项目列表右键菜单和现有省略号菜单共用操作项，新增“使用编辑器打开”。传入被操作项目的 rootPath，复用应用现有 IDE 配置、选择器和 IPC，不以当前选中项目代替右键目标。

用户手动触发分析后，Agent 检查并修复项目；应用接着运行 package.json 的 scripts.build（存在时），然后校验 autoforge.json 的入口和语言语法，全部通过才导入 Autoforge。构建失败提供诊断，允许本轮 AI 自动修复并重新构建检查。无 build 脚本的 JavaScript/Python 项目直接检查导入。不自动安装依赖，不改变普通对话的导入边界。

选择固定的 npm run build 约定，避免另设一套构建配置。直接导入源码无法覆盖入口由构建生成的项目；允许模型自行执行任意命令则超出当前工具职责。

按最新两张截图删除主导航品牌行、脚本上下文侧栏底部的四个重复快捷入口。主导航保留原有功能入口。

## 实现与验证

- 构建器限制诊断输出，默认两分钟超时；取消或超时终止构建进程树。
- Agent 的检查阶段先构建再执行包、语法检查；错误沿用现有修复回路。
- 使用真实 npm 构建 fixture 验证中文路径、失败、取消、超时，验证 dist 入口生成后通过检查并实际导入。
- 浏览器验证右键未选中项目时打开正确目录，保持原项目会话；继续覆盖 Markdown、素材与运行期间切页回归。
- 浏览器夹具共享 Vite 优化缓存，因此测试文件串行运行，避免不同配置同时重写缓存。

## 影响与边界

仅影响 autoforge：AI 项目服务、项目操作菜单及导航展示。复用现有脚本注册表更新规则与 IDE IPC，不新增公共 IPC 契约。构建依赖由用户项目自行准备；目录中的符号链接仍按现有包安全规则处理。
