# 详情面板运行参数与配置自动保存设计

## 目标

让脚本详情面板“运行参数”和“配置”两个 Tab 的修改自动持久化并立即生效，不再要求用户点击底部保存按钮。文本/文本域停止输入约 400ms 后保存，选择框、复选框、附件等字段变更后进入同一自动保存队列；批量运行面板的实例预设继续使用手动保存。

## 当前根因

- `src/renderer/src/components/DetailPanel.vue` 中的 `paramVars` 和 `envVars` 只是本地响应式草稿。
- 只有 `saveParams()` 才调用 `window.autoforge.scripts.setParams`，只有 `saveConfig()` 才调用 `setEnvConfig` 和 `scripts.update`。
- `SchemaValueField` 的输入事件只更新 `v-model`，不会自动触发上述保存函数，因此用户必须点击底部按钮。
- dirty 快照必须从响应式对象直接读取；仅在生成 IPC payload 时转换为普通对象，不能在计算 dirty 状态时使用 `toRaw`，否则嵌套输入变化不会触发快照更新。

## 方案

### 作用范围

- 改造详情面板的“运行参数”和“配置”两个 Tab。
- 编辑 `autoforge.json` 的手动保存流程保持不变。
- `BatchRunPanel.vue` 的实例配置/参数预设继续保留手动保存按钮，不修改其行为。

### 自动保存触发

- 深度监听 `paramVars`，与当前环境已有参数快照比较；有实际差异时启动 400ms 防抖。
- 深度监听 `envVars`、`cronExpression` 和 `cronEnabled`，与当前环境已有配置/定时任务快照比较；有实际差异时启动 400ms 防抖。
- `SchemaValueField` 的 select、radio、checkbox、boolean、attachment 也通过同一 watcher 保存，不新增字段级事件 API。
- 切换环境只同步对应环境的表单值，不把加载过程视为用户修改；用户切换默认环境的选择会进入配置保存队列。

### 保存队列与并发

- 参数和配置分别维护 timer、in-flight 标记、queued 标记和已保存快照。
- 请求进行中再次修改时只标记 queued；当前请求完成后基于最新表单快照发起下一次请求。
- 快照相同则跳过 IPC，避免初始化、刷新或重复失焦产生无效写入。
- 保存成功后触发 `refresh`，并通过现有 `usePanelSaveFeedback` 显示“已自动保存”；失败保留本地值并显示错误，下一次修改可重试。

### 参数保存

- 复用现有 `setParams(scriptId, envId, values)`。
- 自动保存前继续执行 `cleanupAttachmentDiff(..., 'removed')`，清理被移除的附件。
- 保存前记录当前环境和参数快照；请求完成后如果用户已切换环境或形成新差异，不覆盖当前本地输入，由 queued 流程继续保存。

### 配置保存

- 复用现有 `setEnvConfig(scriptId, envId, values)`，再用 `scripts.update` 写入 `defaultEnvId` 和定时任务。
- 定时任务表达式、启用状态与环境变量在同一次自动保存中提交，避免出现只保存一半的状态。
- 点击运行前先刷新待处理参数/配置保存，确保运行读取到最新持久化值。

### 界面变化

- 删除“运行参数”Tab 底部的“保存/取消”按钮。
- 删除“配置”Tab 底部的“保存配置”按钮。
- 详情面板顶部继续显示保存反馈，但文案使用“正在保存…”、“已自动保存”和“保存失败”。
- 自动保存期间字段保持可编辑；“编辑 autoforge.json”和“批量运行”仍显示原手动保存操作。

## 生命周期与边界

1. 详情面板加载脚本或切换环境时写入本地表单和已保存快照，暂停自动保存。
2. 用户修改表单后，watcher 比较快照并调度对应保存队列。
3. 切换环境、切换脚本或关闭详情面板时，先刷新待处理 timer；参数/配置请求继续完成，不丢失最后一次修改。
4. `props.script` 刷新返回新数据时，仅当本地没有对应 dirty 状态才同步表单，避免覆盖用户正在输入的值。
5. 自动保存不改变批量运行实例预设、脚本清单编辑和 IPC 公共接口。

## 错误处理

- IPC 返回空结果或抛错时视为保存失败，保留用户当前表单值。
- 附件清理失败时不提交后续参数变更，显示错误反馈；下一次表单修改可重试。
- 关闭面板不会取消已经发出的 IPC，请求完成后仍更新持久化数据和反馈状态。

## 验证

- 运行 `npm run lint` 和 `npm run build`。
- 运行现有 `npm run test:unit`，确认共享逻辑和现有面板测试不回归。
- 手动验证：参数文本连续输入、参数 select/checkbox/附件、配置环境变量、定时任务、环境切换、脚本切换、点击运行前刷新、保存失败重试。
- 确认两个目标 Tab 不再出现手动保存按钮，编辑 Tab 与批量运行面板仍保留手动保存。
