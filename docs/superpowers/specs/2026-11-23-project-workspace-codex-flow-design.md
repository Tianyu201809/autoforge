# 项目工作区与 Codex 式交互设计

**日期**：2026-11-23
**状态**：已批准（方案 2，2026-11-23）
**范围**：Autoforge 项目工作区、手动 AI 检查与导入，以及截图 3/4 指出的工作区布局

## 意图

让 AI 项目工作区的页面结构和操作节奏贴近 Codex：用户能在项目列表切换本机项目，在会话区与 Agent 协作，并查看文件变更和检查结果。文件修改后不应自动检查或导入；用户明确触发后，再由 AI 分析项目、执行 Autoforge 包和语言语法检查，并在通过后导入或更新关联脚本。

截图 3/4 还要求把脚本工作区的上传入口移到侧栏顶部，并调整侧栏拖动边界，使脚本导航、上传按钮和主内容区的关系更清楚。

## 目标与边界

- 项目工作区采用 Autoforge 自有样式的 Codex 式三栏结构：全局导航、项目侧栏、会话主区和可折叠/调整宽度的检查侧栏。
- 项目侧栏提供新建、切换与项目操作；会话主区保留历史消息、流式响应、取消任务和多行输入。
- 检查侧栏集中展示本轮文件变化、AI 分析摘要、包/语法检查结果、关联脚本及明确的手动检查/导入操作。
- 每轮 Agent 修改文件后仅保留变更并结束当前对话任务，不自动触发检查或导入。用户手动触发后，Agent 分析当前项目文件并给出/执行必要处理，然后运行确定性的包校验和语法检查；检查失败时保留诊断并允许用户继续对话修复；通过后导入或更新关联脚本。
- 检查和导入要能区分“尚未检查”“检查中”“检查失败”“检查通过待导入”和“已导入”，避免把检查通过误显示为已导入。
- 脚本工作区的“上传脚本”按钮移至截图 3 所示的侧栏顶部；底部保留 Hub、指南、历史和设置快捷入口。截图 4 所示侧栏与内容区边界作为一个连续可拖动分隔控制，拖动时侧栏增宽、主内容区相应让位，不产生独立空白拖动槽。
- 延续现有项目数据、模型设置、主题、键盘操作和本机文件保护。

非目标：复刻 Codex 品牌资产或逐像素实现；修改模型供应商或凭据体系；自动运行导入后的脚本；改动脚本包契约；在此轮设计内重做脚本库卡片、执行控制或全局导航语义。

## Approaches

1. **保留现有 AI 项目视图并局部补丁**：在当前内部三栏布局上加入手动操作按钮，再修正脚本侧栏布局。范围最小，但 AI 项目列表仍像独立管理面板，难以达到 Codex 式会话体验。
2. **Codex 式项目工作台（建议）**：统一项目侧栏、对话主区和检查侧栏的层级、折叠及拖动行为；把检查/导入建模为用户显式触发的流程；另外按截图 3/4 调整脚本工作区上传按钮和侧栏边界。能同时覆盖交互和视觉目标，需协调现有 `WorkspaceShell` 与 `AiProjectWorkspace` 的宽度/面板职责。
3. **重做全局应用壳层**：所有脚本、项目、历史、Hub 页面都迁移为统一的 Codex 式会话型导航。超出本次对项目工作区及两张布局截图的范围，也会扩大回归面。

建议采用方案 2。实现时沿用现有 Vue/Electron 工作台、布局状态持久化和主题 token，不另引入 UI 框架。

## 页面草图

│          │                        │                               │ 包与语法检查        │
│          │                        │ [输入需求……          发送]     │ [分析并检查/导入]   │
└──────────┴──────────────────────┴─────────────────────────────┴──────────────────┘

脚本工作区侧栏顶部： [上传脚本]  [搜索……]

## 行为与状态

### Agent 对话

- 普通发送仍允许 Agent 读取、创建和修改当前项目文件，保留现有路径限制、哈希并发保护、取消与流式响应。
- 完成文件修改后不再自动执行 `runChecks`，也不在系统提示中要求 Agent 自动调用 `import_script`。Agent 可总结变更，项目状态回到可继续协作状态。
- 检查侧栏的主动作在项目有内容且当前没有运行任务时可用。用户触发后启动一次面向当前磁盘内容的 AI 分析/处理流程；Agent 只能使用现有受限项目文件工具，可以直接修改项目文件并自动复检；之后运行包校验及语言语法检查。
- 只有两类检查都通过，才执行导入或更新。失败时显示诊断，保留文件和分析结果，不导入。用户可以修复后再次触发。
- 若项目已有关联脚本，成功动作更新该脚本；否则首次导入并保存关联。该动作不会自动运行脚本。
- 重试/重新检查应沿用明确触发的流程，按钮文案说明是否包含 AI 分析。不得留有可绕过“用户触发”的隐藏自动导入入口。
- 用户已确认：本次显式触发的 AI 分析发现问题时，允许 AI 直接修改文件并重新检查。

### 布局

- 项目区使用左项目列表、中间会话、右检查面板。检查面板宽度与可见性由唯一布局所有者控制，拖动边界与面板一起工作，宽度和折叠状态延续现有持久化方式。
- 关闭检查面板后会话区扩展；窄窗时检查面板采用抽屉，关闭/打开按钮保持可发现。
- 脚本页复用现有 `WorkspaceContextSidebar` 的宽度状态。拖动分隔线应调整完整上下文侧栏宽度，并让主内容区域同步伸缩；视觉分隔与拖动热区连续，不出现截图 4 红框指出的独立狭长块。
- 按截图 3 将上传按钮放在脚本侧栏顶部、搜索框与导航项之前；底部只保留快捷入口。保持文件选择、拖放导入及现有导入校验行为不变。

## 约束与实现范围

- 主进程继续负责路径校验、项目文件操作、包/语法检查、脚本导入和关联记录；renderer 仅发起用户动作并显示状态。
- 优先复用现有 Agent turn、工具、检查器和 `ProjectRegistry`，仅调整自动调用边界并增加显式工作流入口；若需要新的 IPC/API，应保持项目 ID 校验和并发锁。
- 同一项目不可并行启动聊天写入与检查/导入流程。触发期间禁用会修改文件或重复检查的操作，并支持取消时恢复一致状态。
- UI 行为必须覆盖首次项目、已有项目未检查、检查失败、检查通过待导入、已关联脚本更新、空状态和窄窗口。
- 可能涉及 `AiProjectWorkspace.vue`、`useAiProjectWorkspace.ts`、AI Agent service/tools/IPC 及对应测试，以及 `WorkspaceShell.vue`、`WorkspaceContextSidebar.vue` 和脚本 `Sidebar` 组件。最终边界由实现者依据现有组件责任决定。

## 验收标准

1. Agent 对话写入文件后，不自动运行包/语法检查，也不自动导入或更新脚本。
2. 用户按下显式的 AI 分析/检查/导入主动作后，当前项目被分析并处理，包校验和语言语法检查顺序执行；仅全部通过时导入/更新。
3. 检查失败可查看诊断，项目文件保留，能继续对话修复并手动重试；检查通过和导入完成是不同状态。
4. 对已关联脚本的项目，成功动作更新现有关联；未关联项目成功导入后建立关联；均不自动运行脚本。
5. 项目工作区列表、会话与右侧检查面板能独立浏览；面板可关闭、恢复、拖动调宽，窄窗口使用可关闭抽屉。
6. 脚本页上传按钮出现在截图 3 所示的侧栏顶部；底部快捷入口保留。拖动截图 4 的侧栏边界时，侧栏整体扩宽、主内容同步收缩，边界无孤立空白控制块。
7. 现有项目管理操作、脚本拖放导入、主题、键盘可用性和脚本运行行为保持正常。

## 留给实现者的决定

- 在不重复持久化数据的前提下，AI 分析摘要与过程事件如何放入现有 `AiProjectTurn`/事件模型。
- 如何让显式分析流程与普通 Agent 对话共享安全工具和取消机制，同时防止自动调用导入工具。
- 项目工作区检查面板尺寸状态应复用现有 `inspectorWidth`，还是新增项目专属宽度字段；优先避免影响其他页面的宽度偏好。
- 组件拆分及布局层状态所有权，以消除目前项目视图内置检查栏与通用 `WorkspaceShell` 检查栏职责分离的问题。
