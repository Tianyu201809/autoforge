# 设置页侧边分类与自动保存设计

## 目标

将当前单页纵向设置弹窗改造成侧边分类点击切换的双栏设置页，并移除依赖“保存设置/保存环境”按钮的提交方式。用户修改配置后，窗口行为立即生效；普通配置在输入框失焦时自动保存；环境 Profile 的编辑在修改后自动保存。

## 当前上下文

- 设置入口位于 `src/renderer/src/components/SettingsPanel.vue`，通过 `AppFeatureModal` 显示。
- 现有弹窗使用 `max-width="2xl"`，所有设置区块位于一个滚动列中。
- 普通配置通过 `window.autoforge.config.get/set` 读写。
- 托盘、悬浮球、全局快捷键通过 `window.api.setMode()` 即时应用，并由主进程持久化窗口配置。
- 环境 Profile 通过 `window.autoforge.env.list/create/update/delete` 管理。

## 设计

### 信息架构

将设置划分为五个侧边分类，默认打开“概览”，并在设置弹窗本次打开期间记住最近选择的分类：

1. **概览**：产品版本、AutoforgeHub 地址。
2. **窗口与外观**：托盘模式、悬浮球、全局快捷键、皮肤选择。
3. **环境与运行**：环境 Profile、浏览器路径、Python 状态与路径、pip 镜像、运行超时、全局 Python 依赖。
4. **开发工具**：外部编辑器路径。
5. **日志与数据**：日志级别、打开数据目录。

创建/删除环境、安装/移除全局依赖等明确动作按钮保留；移除“保存设置”和“保存环境”按钮。

### 布局与视觉

- 将 `AppFeatureModal` 的设置弹窗宽度从 `2xl` 调整为 `5xl`，继续使用现有遮罩、圆角、边框、阴影和主题 CSS 变量。
- 设置内容根节点固定为 `min(92vh, 880px)` 高度，右侧内容独立滚动；分类内容较少时保留空白，避免弹窗随分类内容自动缩放。
- 顶部标题栏保留图标、标题、描述和关闭按钮，在右侧增加统一的自动保存状态文本。
- 主体使用固定左栏 + 独立右侧滚动内容区。左栏宽度约 176px，导航项使用现有主题色、选中强调线和轻微背景填充。
- 右侧沿用当前卡片、表单和皮肤选择器样式，只调整区块间距与内容宽度，不引入新的 UI 依赖。
- 窄窗口下切换为顶部横向可滚动分类条，避免固定侧栏挤压输入控件。
- 分类按钮为语义化 `button`，当前项设置 `aria-current="page"`；自动保存状态使用 `aria-live="polite"`。

### 配置自动保存

在 `SettingsPanel.vue` 内保留现有字段 refs，新增统一的配置 patch 构建和保存状态管理：

- `buildConfigPatch()` 按当前字段构建 `hub`、`browser`、`python`、`script`、`externalEditor`、`logLevel` 等配置分组。
- Hub 地址、浏览器/Python/编辑器路径、pip 镜像和运行超时等文本输入在失去焦点时触发保存；保存前清理空白值，数值超时取非负整数或未设置。
- 日志级别等离散配置在变更后立即保存；皮肤选择继续复用 `useTheme()`，变更后立即应用并写入现有 `localStorage`，不进入 `config.set`。
- 托盘、悬浮球、全局快捷键继续通过现有 `window.api.setMode()` watcher 即时应用和持久化，避免重复调用普通配置保存接口。
- 初始化读取配置和窗口状态时暂停 watcher；初始化完成后才允许自动保存。
- 顶部状态在保存期间显示“正在保存…”，成功显示“已自动保存”，失败显示失败状态并通过 Toast 提示；失败不会清空用户当前输入，下一次有效修改可再次保存。

### 环境 Profile 自动保存

- 深度监听当前 `editingEnv`，名称、默认环境状态、环境变量新增/修改/删除后触发自动更新。
- 环境编辑保存采用现有 `window.autoforge.env.update`，传入纯 JSON 对象，避免把 Vue reactive Proxy 传入 IPC。
- 环境修改使用 400ms 防抖，防止连续编辑变量值时重复请求；环境选择只切换当前编辑对象，不触发保存。
- 创建和删除环境仍在点击后立即调用现有 API；成功后刷新环境列表、重新定位当前环境并发出 `environments-changed`。
- 保存成功更新环境列表并显示状态；失败保留编辑内容并通过 Toast 提示。

### 组件边界

- `SettingsPanel.vue` 继续作为设置弹窗容器、导航状态和自动保存协调器。
- 可在同一文件内提取小型纯函数（分类元数据、配置 patch 构建、保存状态文案），不改变现有 IPC 公共接口。
- `AppFeatureModal.vue` 仅接收新的宽度使用方式，不承担设置业务状态。
- `SkinPicker.vue`、`ShortcutRecorder.vue` 和现有环境/依赖 API 保持公开接口不变。

## 数据流与错误处理

1. 打开设置弹窗后读取配置、窗口模式、浏览器/Python 状态、依赖和环境列表。
2. 初始化完成后开启配置字段和当前环境的 watcher。
3. 用户修改字段时，按照“失焦保存/立即保存/环境 400ms 防抖”规则生成最小 patch 并调用对应 IPC。
4. IPC 成功后更新保存状态；环境保存成功额外刷新环境列表并通知主界面。
5. IPC 失败时保留本地编辑值，显示 Toast 错误和失败状态，不阻塞用户继续修改。
6. 关闭弹窗时先刷新仍在队列中的自动保存；文本输入通常在失焦时触发保存，环境修改由 watcher 自动调度，关闭不会丢失最后一次已发生的修改。

## 兼容性与非目标

- 不修改 `AppConfig`、`EnvironmentProfile`、IPC channel 或数据库结构。
- 不改变窗口模式、Python 检测、依赖安装和皮肤选择的现有业务行为。
- 不新增第三方依赖，不把设置页改成独立路由或新窗口。

## 验证

- 运行 `npm run lint`，确认 Vue/TypeScript 与模板检查通过。
- 运行 `npm run build`，确认生产构建通过。
- 手动验证：五个分类点击切换、默认分类和会话内记忆、关闭重开、文本失焦自动保存、离散控件即时保存、窗口行为即时生效、环境编辑自动保存、环境创建/删除、依赖安装/移除、错误 Toast、窄窗口横向分类条。
- 检查自动保存请求只在实际修改后发送，初始化赋值不会触发保存，切换环境不会误保存上一项。
