# 本地文件夹与文件导入为转换工作区 — 设计规格

**日期**：2026-10-02  
**状态**：待实现  
**关联**：`docs/superpowers/specs/2026-09-30-repo-to-script-design.md`（画像、两阶段 LLM 转换）、`docs/superpowers/specs/2026-10-01-repo-conversion-chat-design.md`（工作区对话与删除）

---

## 1. 目标

仓库工作区现在只能从 GitHub / Gitee 拉取。用户还要能在同一页把一个本地文件夹，或同一次选中的多个文件，复制成一个新工作区，然后用现有的对话做 LLM 转换。

导入只创建工作区。转换仍由用户点「开始转换」。原文件夹保持不动。删除工作区只删除这份副本。

## 2. 已确认决策

| 项 | 选择 |
|----|------|
| 一次导入 | 一个文件夹，或同一次选择 / 拖入的多个路径，成为一个工作区 |
| 目录结构 | 能算出可用的共同父目录时保留相对路径；父目录过高时只留文件名 |
| 转换时机 | 和工作区拉取成功一样，打开对话，不自动开始转换 |
| 文件去向 | 复制到工作区。原路径不改、不删 |
| 删除 | 只删除工作区副本。已导入的脚本仍留在脚本列表 |
| 入口 | 只在仓库工作区页面。主窗口现有的脚本拖拽不变 |
| 不做 | zip；自动开始 LLM；把本地目录伪装成 GitHub 仓库 |

## 3. 工作区与画像

本地导入使用和拉取相同的目录：

```
<userData>/repo-workspaces/<taskId>/
├── repo/                 # 复制进来的本地内容
└── .autoforge/           # profile、handoff、对话、产物
```

`RepoProvider` 增加 `'local'`。`RepoFetchMethod` 增加 `'local'`。本地画像：

- `ref.provider` 为 `'local'`
- `ref.owner` 为空字符串
- `ref.repo` 为下面的显示名
- `ref.url` 为可显示的根路径；压平导入时为空字符串
- `ref.cloneUrl` 为空字符串，不用于拉取
- `ref.transport` 记为 `'https'`，本地导入不读取它
- `fetchMethod` 为 `'local'`
- `resolvedRef` 为 `本地目录`
- `commitSha` 为 `null`

另外记下用户选中的原始绝对路径、是否压平，以及未压平时的根路径。这些字段只用于显示和测试，不参与模型提示词。模型看到的仍是复制后的 `repo/` 目录经现有 digest 生成的上下文。

显示名：

- 只选中一个文件夹：该文件夹的名称
- 只选中一个文件：该文件的名称
- 多个路径且保留了目录结构：共同父目录的名称
- 压平后的多个文件：`本地文件`

列表标题用别名，没有别名时用显示名。列表副标题为「本地目录」。对话标题同样用别名或显示名。对话副标题以「本地目录」开头；有根路径时接上该路径，压平时接上「多个位置」。画像里的可转换性说明可以继续显示在后面。

已有的 GitHub / Gitee 工作区字段不变。列表在 `provider === 'local'` 时，`repo` 用显示名，不用 `owner/repo`。

拉取成功时会写的 handoff 文件，本地导入也写一份，避免打开工作区时缺文件。页面不因此恢复外部 Agent 或复制提示词。

## 4. 复制规则

主进程把选中的路径复制到该工作区的 `repo/`。

- 选中的是唯一一个文件夹：把它的子项复制到 `repo/` 根目录，不再多套一层同名目录。
- 其他情况：用这些绝对路径的最近共同父目录计算相对路径，放到 `repo/` 下。
- 共同父目录是盘符根、用户主目录，或主目录的祖先时，视为过高。不同盘符也视为过高。这时每个文件只保留文件名。
- 压平之后基名相撞：整次导入取消。
- 不跟随符号链接。链接本身不复制。
- 复制时跳过这些目录名：`.git`、`.hg`、`.svn`、`node_modules`、`bower_components`、`.venv`、`venv`、`__pycache__`、`.mypy_cache`、`.pytest_cache`、`.tox`、`.ruff_cache`、`.cache`、`coverage`、`site-packages`。
- `dist`、`build`、`out`、`target`、`vendor` 以及名为 `env` 的目录要保留。它们可能是待转换的源码或构建结果。
- 跳过之后没有任何文件：整次导入取消。
- 待复制文件超过 6000 个，或总字节超过 200 MB：整次导入取消。
- 任一源路径位于 `repo-workspaces` 之内，或复制目标越出本次 `repo/`：整次导入取消。
- 复制中途读失败或写失败：整次导入取消。

取消时删除本次新建的整个 `<taskId>/` 目录。用户原来的文件保持不动。不留下只有画像、没有文件的工作区。

## 5. 页面

入口只在仓库工作区页面。

- 侧栏按钮「拉取」改为「新建」。正在拉取、复制或 LLM 转换时，该按钮不可用。
- 空列表文案改为「还没有工作区。」
- 侧栏说明改为：删除工作区时，这里的副本会一起删除，原来的文件夹不会动。已经导入的脚本会留在列表里。
- 新建表单保留现在的仓库地址、分支和令牌。其下增加本地区域：把文件夹或文件拖到这里，以及「选择文件夹」「选择文件」。选择文件允许多选。
- 正在拉取或复制时，本地区域不可用。
- 拖拽和选择框都通过现有的 `webUtils.getPathForFile` 路径读取，得到绝对路径后再交给主进程。
- 用户关掉选择框：不提示，表单保持原样。
- 复制过程中，表单状态处显示「正在复制到工作区」。
- 成功后关闭新建表单，打开该工作区的对话。不调用模型。
- 失败文字显示在新建表单上，与拉取失败同一处。
- 右键菜单仍是设置别名和删除工作区。删除确认沿用现有对话框。本地工作区的正文写「工作区里的副本」，不写「克隆的仓库」。从 Git 拉取的工作区确认文案保持不变。

主窗口上的脚本拖拽不创建工作区。

## 6. 数据流

新增 `repo:import-local`，参数为绝对路径字符串数组。主进程：

1. 与拉取共用同一个忙碌锁。已在拉取或复制时拒绝，提示「已有内容正在准备」。
2. 校验路径、计算布局、复制、用现有的目录分析写出画像和 handoff。
3. 返回现有的 `RepoWorkspaceInfo`。

渲染进程收到后，像拉取成功一样选中该工作区。此 IPC 不调用 LLM，不写入对话轮次。

## 7. 错误提示

| 情况 | 结果 |
|------|------|
| 关闭选择框，或拖入没有路径 | 无提示 |
| 已有拉取或复制在进行 | 「已有内容正在准备」 |
| 跳过之后没有文件 | 「没有可复制的文件」 |
| 压平后文件名相撞 | 「这些文件压平后会重名，请改成选择它们所在的文件夹。」 |
| 超过 6000 个文件或 200 MB | 「本地导入超出上限：最多 6000 个文件、200 MB。」 |
| 源路径在工作区目录内，或目标越界 | 「不能把工作区目录再次导入」 |
| 复制中途失败 | 「复制失败，工作区未创建。」原文件仍在，半成品目录已删除 |

## 8. 测试

用临时目录测试主进程规则，不点击窗口。

- 单个文件夹的子项位于 `repo/` 根目录。
- 多个文件按共同父目录保留相对路径。
- 父目录为盘符根、用户主目录或其祖先，以及路径位于不同盘符时，只保留文件名。
- 压平后重名则失败，且不留下工作区目录。
- `.git`、`node_modules`、`.venv` 不在副本里；`dist` 在。
- 符号链接不跟随。
- 没有可复制文件、超过文件数、超过 200 MB、源路径位于工作区内部、复制中途失败：半成品目录不存在，源文件仍在。
- 成功画像的 `provider` 与 `fetchMethod` 为 `local`，显示名与原始路径符合第 3 节。
- 现有仓库拉取测试仍然通过。

## 9. 非目标

- 导入 zip。
- 在主窗口拖入文件夹或文件来创建工作区。
- 导入后自动开始 LLM 转换。
- 删除或改写用户原来的文件夹。
- 跟随符号链接。
- 为本地导入单独做一套对话或转换流程。
