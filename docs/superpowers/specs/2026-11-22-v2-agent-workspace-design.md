# Autoforge v2.0 AI Agent 工作区与界面重构设计

**日期**：2026-11-22
**状态**：设计已批准，实施计划待审阅
**目标版本**：v2.0.0
**适用范围**：Autoforge 桌面应用

## 1. 目标

Autoforge v2.0 为用户提供 AI Agent 项目工作区。用户选择本机项目文件夹，通过多轮对话创建和修改 JavaScript 或 Python Autoforge 脚本。Agent 可以读取项目文件、提出文件改动并应用到工作区。每轮改动完成后运行脚本包契约校验和语言语法检查。检查通过后，应用自动将脚本导入 Autoforge 脚本库。

用户还要求对整个应用进行 Codex 式布局重构。工作区、AI 对话、文件变更、验证结果和脚本管理共用统一导航与内容框架，减少现有功能之间的页面割裂。

## 2. 设计决策

| 项目 | 决策 |
|---|---|
| 项目目录 | 用户每次通过系统目录选择器选择本机文件夹，选定目录作为项目根目录 |
| 新项目目录状态 | 首次创建接受存在、可写的本机文件夹，可包含已有文件；Agent 文件工具以哈希检查保护并行编辑 |
| 后续文件修改 | Agent 只可读取和修改项目根目录内的安全相对路径；每轮保留变更摘要 |
| 脚本语言 | 首期生成 JavaScript 和 Python Autoforge 脚本包 |
| 自动验证 | 使用现有脚本包校验，加 JavaScript / Python 语法检查；验证全部通过后自动导入 |
| 脚本运行 | 导入后不自动运行。用户通过现有运行入口启动脚本 |
| 模型协议 | 原生支持 OpenAI、Anthropic、Gemini；另支持 OpenAI 兼容 API |
| 模型覆盖 | 兼容端点提供 OpenAI、DeepSeek、Qwen、GLM、Kimi 常用预设，也允许自定义地址、模型名和请求头 |
| 凭据 | API Key 仅由主进程处理，使用 Electron `safeStorage` 加密保存；渲染进程只读取密钥是否已配置 |
| UI | 采用 Codex 桌面应用的导航、项目列表、主工作区和可折叠侧栏布局，延用 Autoforge 的品牌资产、主题和脚本领域语言 |
| 既有能力 | 通过新工作台统一进入脚本库、执行历史、脚本中心、开发指南和设置，保留既有业务行为 |

## 3. 方案比较

| 方案 | 做法 | 取舍 |
|---|---|---|
| 在现有脚本库增加 AI 页签 | 保留当前主界面，增加一个生成脚本入口 | 改动较小，但对话、项目文件、脚本库仍是分离体验，无法满足整体布局重构 |
| 多供应商 Agent + 统一工作台 | 统一 Agent 会话协议，接入原生供应商和兼容端点；重排全局导航、项目列表、对话主区和文件/验证侧栏 | 改动范围较大，但同时满足模型覆盖、项目工作流和全局 UI 目标 |
| 仅使用 OpenAI 兼容接口 | 所有模型共用一种请求格式 | 接入简单，但不能满足 Anthropic 和 Gemini 原生接口支持，且不同兼容服务仍需处理端点差异 |

**采用方案**：多供应商 Agent + 统一工作台。UI 复用成熟的三栏工作台信息架构，不复制 Codex 品牌资产或逐像素样式。这样能保持 Autoforge 的脚本运行、环境配置和执行历史语义，同时让项目对话成为主要工作入口。

## 4. 用户流程

1. 用户从主导航打开「项目」，选择「新建项目」。
2. 系统目录选择器返回本机文件夹。主进程确认目录存在、可写、非符号链接且为空。
3. 用户填写项目名称、用途和脚本语言，并选择模型配置。
4. Agent 创建项目会话并通过流式对话生成或调整文件。工作区显示 Agent 正在做的动作、文件变更和阶段状态。
5. 每轮应用改动后执行清单校验和对应语言的语法检查。失败时保留项目文件和检查结果，Agent 可根据诊断继续修复。
6. 所有检查通过后，主进程通过 `scriptRegistry.importFromPath` 导入脚本。项目文件夹保留在原位置，导入的脚本副本进入 Autoforge 脚本目录。
7. 用户可以继续在项目工作区修改文件。每次通过检查后，应用更新该项目关联的已导入脚本；用户仍需显式运行脚本。

## 5. 工作台布局

```text
┌──────────────────┬─────────────────────────────┬──────────────────────┐
│ 导航与项目列表     │ 当前项目 / Agent 对话          │ 文件、变更与检查        │
│                  │                             │                      │
│ 新建项目          │ 项目名称与当前任务             │ 项目文件树             │
│ 项目              │ 对话消息与 Agent 操作          │ 本轮改动               │
│ 脚本库            │                             │ 包校验 / 语法检查       │
│ 执行历史          │                             │ 导入状态               │
│                  │                             │                      │
│ 模型与设置        │ 固定在底部的对话输入区          │ 可折叠或隐藏           │
└──────────────────┴─────────────────────────────┴──────────────────────┘
```

- 左侧包含全局导航和最近项目，可折叠并记住宽度。项目按最近更新时间排序。
- 中央为当前项目、对话记录、Agent 状态和输入区。输入区支持多行文本、模型选择、取消生成和重试。
- 右侧为项目文件、变更摘要、验证结果和导入状态，可关闭以扩大对话区域。
- 脚本库沿用列表、详情和执行控制能力，但进入统一工作台壳层。执行日志可沿用现有底部面板并支持弹出。
- 小窗口下右侧面板改为抽屉，左侧导航收起为图标栏，保证主对话仍可用。
- 保留现有浅色/深色主题和无障碍键盘操作。新增布局需要在窄窗下可用，不遮挡输入和验证状态。

## 6. Agent 与模型架构

### 6.1 供应商层

新增统一的 `LlmProviderAdapter` 契约，向 Agent 层提供流式对话、取消、错误分类、token 使用信息和工具调用结果。

| 适配器 | 覆盖范围 |
|---|---|
| OpenAI adapter | OpenAI 原生 Chat Completions API、SSE 流和工具调用 |
| Anthropic adapter | Messages API、SSE 流、工具调用和对应鉴权头 |
| Gemini adapter | `generateContent` / 流式接口、函数调用和对应鉴权 |
| OpenAI-compatible adapter | DeepSeek、Qwen、GLM、Kimi、硅基流动及自定义兼容端点 |

配置视图包含供应商类型、配置名称、端点、模型、API Key、额外请求头和超时。API Key 与额外请求头的值都进入加密凭据存储，非敏感模型配置留在 SQLite。适配器负责将供应商响应映射为统一事件，不让 Vue 页面理解供应商协议。

兼容端点预设只提供当前已验证的基础地址模板，用户可修改地址和模型名。模型名称不硬编码到供应商能力判断中。连接测试从主进程执行并返回简短状态，不返回密钥或完整鉴权头。

### 6.2 Agent 工具

Agent 通过结构化工具调用与主进程交互，不直接获取任意命令执行权限。

| 工具 | 行为与边界 |
|---|---|
| `list_project_files` | 列出根目录内普通文件，跳过 `.git`、依赖目录、符号链接和应用私有元数据 |
| `read_project_file` | 读取限定大小的 UTF-8 文本文件 |
| `write_project_files` | 写入或替换安全相对路径，应用前生成变更记录并检查根目录边界 |
| `validate_script_package` | 验证 `autoforge.json`、入口文件和现有脚本包契约 |
| `check_script_syntax` | 对 JavaScript 执行固定参数的 `node --check`；对 Python 使用配置解释器运行固定的 AST 语法检查，不写入 `__pycache__`，不调用脚本入口 |
| `import_script` | 仅当包校验和语法检查均通过时调用既有脚本导入路径 |

Agent 不可使用任意 shell、任意网络下载、文件系统根目录访问、进程启动或自动运行生成脚本。首期不运行 `npm install`、`npm test` 或项目自定义构建命令，因为这些命令可执行依赖作者或项目作者的任意代码。语法检查和 Autoforge 包契约校验作为自动导入的检查门槛。

每个 Agent 工具调用由主进程重新校验参数和路径。渲染进程只显示事件，不作为安全决策来源。单个文件大小、单轮文件数、上下文总量和历史长度均设置上限，并在达到限制时向用户说明。

## 7. 项目与导入数据

- 项目根目录为用户选择的本机文件夹。系统拒绝根目录符号链接，使用解析后的绝对路径作为项目身份之一。
- 首轮创建接受非空目录。Agent 先列出普通文件并按需读取，修改已有文件时必须携带预期 SHA-256，以检测项目外的并行编辑。
- 对话和项目索引保存在现有 SQLite 数据库中，不写入脚本包。索引保存项目 ID、根路径、名称、语言、模型配置 ID、更新时间和关联脚本 ID。项目对话单独按项目 ID 关联保存。
- 项目文件仍在用户选择的目录。Agent 只可访问应用确认过的项目根目录范围。
- Agent 文件工具禁止绝对路径、`..`、设备名、符号链接穿越和 Autoforge 私有元数据目录。仅处理普通文本文件。
- 对话保存用户消息、助手摘要、工具调用摘要、检查结果和导入结果。模型思考文本默认不持久化；如供应商返回推理字段，UI 可在当前会话临时展示，且不会作为后续上下文发送。
- 项目根目录由外部编辑器修改后，Agent 重新扫描实际文件。应用不回滚用户在外部做的改动。
- 文件变更以事务批次应用。写入前记录目标文件内容哈希，并在写入时确认文件未被外部修改。写入中失败时，仅当文件仍与本轮写入结果匹配才恢复快照；若发现外部并发改动，保留该文件现状，将项目标记为需人工检查，并禁止自动导入。检查失败的改动保留，供下一轮 Agent 修复。

## 8. 自动检查与导入

每轮生成完成后顺序执行：

1. 校验 Agent 计划结构、文件路径、文件大小和允许的文件类型。
2. 应用变更到所选项目目录并记录本轮改动。
3. 使用 `scriptWorkspace.validatePackageDirectory` 检查清单、语言和入口。
4. 执行对应语言的语法检查。JS 使用当前随应用提供的 Node；Python 使用配置的 Python 解释器。Python 不可用时检查状态为阻断，用户安装或配置 Python 后可重试。
5. 首次通过检查后调用 `scriptRegistry.importFromPath`。导入成功后记录 `scriptId` 与项目关联。
6. 后续通过检查时新增 `ScriptRegistry.updateFromProject`，复用 `ScriptWorkspace.replaceFromDirectory` 的暂存、替换和失败回滚流程，按关联 `scriptId` 更新已导入副本，并保留用户偏好、默认环境、环境值和脚本关联 ID。

自动导入失败不会删除用户项目文件。脚本库导入或更新完成前，现有已导入脚本保持可用。项目页面显示失败步骤、错误摘要和重试入口。此流程不启动脚本，也不自动写入用户的环境变量值。

## 9. 项目状态与会话

```text
new → generating → applying → checking → importing → ready
          │             │          │           │
          └─ cancelled  └─ error   └─ blocked  └─ error
```

- 同一项目同一时间只运行一个 Agent 轮次。
- 用户可取消模型请求。取消后停止工具调用，不启动导入。
- 每轮在应用改动前记录可恢复快照。模型错误、工具错误或检查失败不会自动抹除用户已有文件。
- 检查失败可以让 Agent 根据受限诊断继续修复。达到轮次数上限后停下并显示结果。
- 应用重启时，将未完成的会话标记为中断，保留已保存的消息和文件，不自动续跑工具调用或导入。

## 10. 设置与持久化

- 设置中新增「AI 模型」页面，支持配置新增、编辑、连接测试、设为默认和删除。
- API Key 和额外请求头值单独存储并使用 `safeStorage` 加密，文件结构不写入这些明文凭据。渲染进程只获得 API Key 是否存在、额外请求头名称和加密是否可持久化状态。
- 加密不可用时密钥只保留在当前进程内存，设置页说明重启后需重新输入。
- 对话、项目元数据和模型非敏感配置放在 SQLite 中，API Key 存在独立加密凭据文件中。数据库迁移增加明确版本并在失败时保留原库。损坏的项目记录显示恢复错误，不静默覆盖。
- 所有模型请求由主进程发起；日志、错误、工具结果和诊断信息均对 API Key、额外鉴权头和环境值脱敏。

## 11. 全局 UI 改造范围

- 将主窗口重排为全局导航区、项目/脚本上下文侧栏、中央工作区和可选详情侧栏。
- 将当前模态化的设置、脚本中心、开发指南和执行历史整合到统一导航或工作区路由中，保留各自已有功能。
- 既有脚本列表、分类筛选、运行控制、详情编辑、环境配置、日志面板、Hub 安装、MCP 和窗口模式均需找到等价入口。
- 保留原生拖拽导入、快捷键、独立编辑器/终端窗口和窗口控制行为。
- 不以“Codex 克隆”为产品文案。视觉参考聚焦布局和导航密度，使用 Autoforge 当前图标、主题和脚本管理语义。

## 12. 非目标

- 不执行生成脚本或导入后的脚本作为自动测试。
- 不提供任意 shell/终端命令、任意网络代理、浏览器自动化执行或通用电脑控制。
- 不在首期支持模型自主更改 Autoforge 应用源码或读取项目根目录之外的文件。
- 不生成原生 executable 脚本。
- 不实现云端项目同步或跨设备对话同步。
- 不在模型请求中发送用户的环境 Profile 密钥值或运行日志中的敏感变量。

## 13. 验证要求

### 模型适配器

- 为 OpenAI、Anthropic、Gemini 的鉴权头、流式消息、工具调用、错误映射和取消行为添加协议测试。
- 为 OpenAI 兼容端点测试预设 URL、模型名、自定义请求头、流式回退和错误诊断。
- 连接测试不在日志、IPC 返回值或错误字符串中泄漏 API Key。

### Agent 与文件安全

- 绝对路径、父级路径、符号链接、设备路径、超大文件和非法工具参数均被拒绝。
- Agent 只能读写被选择目录中的允许文件；工具层不能构造 shell 命令。
- 取消、模型失败、文件写入中断和检查失败时不导入脚本。
- JS/Python 语法错误阻止导入；修复并通过两项检查后自动导入。
- 自动导入不启动脚本；更新已导入脚本保留 ID、用户偏好和环境配置。

### 工作台回归

- 新建项目、重开项目、删除/移除项目记录、目录不可用和目录重复占用有明确状态。
- 脚本库、分类、运行/停止、详情编辑、环境设置、执行历史、Hub、MCP、快捷键、拖拽、托盘、编辑器和终端入口均可访问。
- 主工作台验证桌面宽屏和窄窗布局、键盘焦点、侧栏折叠、主题切换及长对话滚动。
- `npm run test:unit`、`npm run lint`、`npm run build` 通过。新增测试必须进入 `test:unit`。

## 14. 实施分期

1. **Agent 基础与模型协议**：模型配置/密钥存储、供应商适配器、流式会话和安全工具边界。
2. **本机项目工作区**：目录选择、项目索引、Agent 对话、文件变更、检查与自动导入。
3. **统一工作台 UI**：新导航壳层、项目/脚本上下文侧栏、中央工作区和右侧检查面板。
4. **兼容与发布**：既有入口回归、迁移旧 UI 状态、版本说明、v2.0.0 发布验证。

项目目录采用“必须为空”的首次创建策略；AI 只做语言语法与脚本包检查，不执行项目命令；项目从导航中移除时只删除 Autoforge 的索引和会话，不删除用户目录；右侧面板默认开启。这些是本设计的实现选择，用户可在审阅时调整。
