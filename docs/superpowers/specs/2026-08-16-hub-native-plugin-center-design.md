# AutoforgeHub 原生脚本中心设计

**日期：** 2026-08-16
**状态：** 已确认，待实施
**关联项目：** `D:/myProject/AutoforgeHub`

## 背景

Autoforge 已能配置并在系统浏览器中打开 AutoforgeHub，也已通过本地 HTTP bridge（`127.0.0.1:19276`）接收 Hub 发起的一键安装请求。AutoforgeHub 已提供 JWT 登录、脚本市场、个人工作区、团队工作区和短时安装令牌。

本功能将 Hub 的已登录脚本浏览和安装体验带入 Autoforge 桌面端。用户可在桌面端登录 Hub，查看有权访问的市场、个人和团队脚本，并直接安装或更新本地脚本。

## 目标

- 在 Autoforge 内完成 AutoforgeHub 的邮箱密码登录、会话恢复和退出。
- 登录后浏览脚本市场、当前用户的个人脚本和所属团队的脚本。
- 支持服务器分页、关键词、分类、语言和现有排序能力。
- 从任意脚本条目一键安装，并复用当前安全 ZIP 导入和重复更新流程。
- 不在渲染进程暴露 JWT、密码或短时下载 URL。
- 保持 Hub 的服务端权限、下载配额和团队下载权限为唯一授权来源。

## 非目标

- 不在桌面端提供注册、找回密码、上传、发布、团队管理或账号资料编辑；这些操作继续在 Hub 网页完成。
- 不嵌入 Hub 网页，不引入 WebView，不同步 Hub 网页的本地存储。
- 不新增离线脚本目录、离线安装或后台自动更新。
- 不修改当前 Hub 网页的一键安装流程。

## 方案选择

采用原生 Electron 脚本中心，而不是嵌入 Hub 网页或继续只打开外部浏览器。

原生方案复用 Hub 现有 API 和 Autoforge 既有 ZIP 安装流水线。主进程持有认证凭据并向 Hub 发起请求，渲染进程仅通过受限 preload API 获取脱敏的会话、列表和安装结果。这样能提供一致的桌面体验，并避免 WebView 的导航、存储、升级兼容性和跨域问题。

## 架构

### 组件职责

| 组件 | 职责 |
| --- | --- |
| AutoforgeHub 服务端 | 登录、JWT 校验、市场/个人/团队列表、详情、下载权限校验、安装令牌签发和 ZIP 代理下载。 |
| Autoforge `hub-client` 主进程服务 | 规范化 Hub URL、登录、会话恢复、带 Bearer 的 API 请求、401 清理、安装令牌申请和错误映射。 |
| Autoforge 凭据存储 | 使用 Electron `safeStorage` 加密 JWT 后保存在应用私有数据中；不放入可导出的应用配置。 |
| preload IPC | 提供登录、退出、会话、列表、详情和安装调用；不返回 token、密码或 `zipUrl`。 |
| 脚本中心渲染组件 | 呈现登录、来源切换、筛选、分页、详情和安装状态。 |
| 既有 Hub 安装器 | 下载一次性 ZIP URL、执行安全解压、导入或更新脚本，并通过现有 Hub 安装事件刷新和选中脚本。 |

### 数据流

```text
脚本中心 UI
  -> preload IPC
  -> hub-client（主进程，持有 JWT）
  -> AutoforgeHub API
       -> /auth/login、/auth/me
       -> /scripts?scope=marketplace|personal|teamId
       -> /teams
       -> /scripts/:id/install-token
  <- 脱敏的会话、列表、详情或错误

安装：
脚本中心 UI -> 主进程申请 install-token -> 临时 zipUrl
  -> 既有 Hub ZIP 安装器 -> 本地脚本注册表
  -> 既有 onHubScriptInstalled 事件 -> 刷新并选中本地脚本
```

## Hub API 契约

桌面端复用下列已存在的 Hub 接口，不引入另一套桌面专用认证或脚本模型：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/auth/login` | 邮箱密码登录，返回 JWT 和用户摘要。 |
| `GET` | `/api/auth/me` | 恢复并验证持久会话。 |
| `GET` | `/api/scripts?scope=marketplace` | 已发布的市场脚本，支持分页、`q`、`category`、`language`、`sort`。 |
| `GET` | `/api/scripts?scope=personal` | 当前用户的个人脚本，支持分页和筛选。 |
| `GET` | `/api/teams` | 当前用户所属团队。 |
| `GET` | `/api/scripts?teamId=<id>` | 当前用户有成员资格的团队脚本。 |
| `GET` | `/api/scripts/:id` | 获取当前用户有访问权的脚本详情和 README。 |
| `POST` | `/api/scripts/:id/install-token` | 按现有下载权限和配额签发 120 秒一次性安装 URL。 |

Hub 必须修正 `GET /api/scripts?teamId=<id>`：在查询前验证调用者为团队 owner 或 member；非成员返回 `403`。该校验与现有详情、下载和安装令牌接口的团队访问规则一致，防止通过构造团队 ID 枚举私有团队内容。

## 认证与凭据

- 登录表单仅向主进程传递邮箱和密码；主进程不会记录密码。
- JWT 使用 `safeStorage.encryptString` 加密，编码后写入 Autoforge 私有应用数据文件；任何配置导出均不得包含该文件内容。
- 启动脚本中心或应用时，主进程解密 JWT 并调用 `/api/auth/me`。成功则返回当前用户摘要；失败、解密失败或 `401` 时清除凭据并返回未登录。
- 退出、Hub 地址变更和服务端返回 `401` 均立即清除凭据。
- 若运行平台无法提供安全加密存储，桌面端不持久化 JWT，当前运行期间仍可使用，重启后要求重新登录，并向用户说明原因。

## UI 与交互

### 入口与登录

- 将侧边栏的“进入 AutoforgeHub”替换为“脚本中心”，在 Autoforge 内打开专用工作台。
- 未登录时显示紧凑的邮箱、密码与登录按钮，并提供“注册账号”和“找回密码”的外部 Hub 链接。
- 已登录时显示头像、显示名称、Hub 地址和退出图标按钮。
- 沿用 Autoforge 的紧凑、低圆角、工具化视觉系统；不复制 Hub 网页的营销布局或整页风格。

### 脚本来源与浏览

- 顶部固定分段控件：“脚本市场”、“我的脚本”、“团队脚本”。
- 团队来源显示当前用户可访问团队的切换器；切换时重新请求该团队的服务端分页结果。
- 工具栏提供搜索、分类、语言和排序。市场排序使用“最新发布 / 安装最多 / 最近更新”；个人和团队使用“最新创建 / 最早创建 / 名称”。
- 列表卡片显示图标、名称、描述、语言、分类、标签、作者或团队、更新时间和市场安装数。详情抽屉额外显示 README。
- 所有列表使用服务端分页，并保留当前来源、团队、筛选和滚动位置；不从其他来源的缓存推断权限或结果。
- 小窗口下，来源切换保持可达；筛选收纳进工具菜单，卡片内容换行而不截断关键信息。

### 安装与更新

- 卡片和详情均提供带图标的安装按钮。一次只允许一个安装请求，其他安装入口在任务期间禁用并保留稳定尺寸。
- 点击安装后，主进程申请安装令牌，再把仅驻留内存的 `zipUrl` 交给既有 ZIP 安装器。
- 已通过 `hubScriptId` 安装的脚本显示“已安装”；点击后表现为“检查更新”，并复用现有原生更新确认对话框。
- 成功时复用 `onHubScriptInstalled`：刷新本地脚本、选中已安装或更新的脚本、显示成功 Toast。
- 取消更新不视为失败，列表恢复可操作状态。

## 错误处理

| 场景 | 桌面端行为 |
| --- | --- |
| Hub 地址为空或无效 | 进入设置页填写合法 `http(s)` 地址。 |
| 网络不可达或超时 | 显示“无法连接 AutoforgeHub”和重试按钮，保留当前筛选。 |
| `401` | 清除凭据，保留筛选并显示重新登录面板。 |
| `403` | 显示“无权访问此脚本或团队”。 |
| `404` | 显示脚本或团队已不可用，并刷新当前列表。 |
| `429` | 显示 Hub 返回的下载配额说明，不重试安装。 |
| `409` | 显示“正在安装，请稍候”，不创建第二个安装任务。 |
| 下载或 ZIP 导入失败 | 显示既有安装器的人类可读错误，不暴露临时 URL。 |

日志中不得写入密码、JWT、Authorization header 或完整的安装令牌 URL。
