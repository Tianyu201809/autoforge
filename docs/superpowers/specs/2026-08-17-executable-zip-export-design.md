# 原生可执行脚本 ZIP 导出设计

## 背景

Autoforge 已支持将 Windows PE、macOS Mach-O 和 Linux ELF 原生程序作为 `language: "executable"` 的脚本导入和运行，但现有 ZIP 导出器会主动拒绝该语言类型。用户需要将原生脚本包连同入口二进制和所需资源导出为可重新导入的 ZIP。

## 目标

1. 支持原生可执行脚本导出 ZIP。
2. 原生包导出整个工作区根目录，保留原有目录结构。
3. 用户无需在清单中逐项声明 DLL、配置和其他运行资源。
4. 保持符号链接、路径越界、依赖目录、缓存、`.env` 与凭据文件的排除规则。
5. 将导出单文件和全部文件的未压缩总大小上限均设为 500 MB。
6. 恢复原生脚本卡片上的导出入口，继续使用现有预览、确认与保存流程。

## 非目标

- 不自动分析 PE、Mach-O 或 ELF 的动态库依赖，也不按扩展名筛选原生包内容。
- 不放宽符号链接、路径越界，以及依赖目录、缓存、`.env` 和密钥证书的排除限制。
- 不改变 JavaScript 或 Python 脚本的静态依赖分析与导出结果。
- 不以 ZIP 压缩后的实际体积作为容量限制依据；限制以纳入文件的未压缩大小计算。

## 方案

扩展现有 `script-package-exporter`，按脚本语言分支构建导出计划，而不是创建第二个导出服务：

- JavaScript/Python 维持当前逻辑：清单、入口、README、`export.include` 和静态解析出的本地代码/资源文件。
- `executable` 分支遍历整个工作区根目录收集文件，不读取或解析二进制内容。清单与入口只做存在性和安全校验，不单独决定 ZIP 内容。
- 原生分支不套用扩展名白名单：配置、数据、构建产物目录都属于程序自身内容，一并导出。
- 原生分支的排除集合收窄为依赖与缓存目录（`node_modules`、`.venv`、`site-packages`、`.git`、`__pycache__` 等）、`.autoforge-*` 内部文件、`.env` 系列，以及 `.pem`、`.key`、`.p12`、`.pfx`、`.crt`、`.cer` 凭据文件。
- 原生分支忽略 `export.include`：整目录已全部纳入，该字段不再有作用，也不因未匹配而报错。
- 所有文件仍必须通过路径规范化、工作区边界、普通文件和非符号链接校验。
- 将 `MAX_FILE_BYTES` 和 `MAX_EXPORT_BYTES` 均改为 500 MB，保留清晰的超限错误。

## 数据流

```text
脚本卡片“导出 ZIP”
  -> IPC 导出预览
  -> buildScriptExportPlan(script, manifest)
     -> executable: 校验清单与入口 -> 遍历整个工作区根目录
     -> javascript/python: 保持现有静态依赖收集
     -> 安全过滤与 500 MB 容量校验
  -> 用户确认并选择路径
  -> writeScriptExportZip()
  -> 返回文件名、文件数和大小
```

## 界面

`ScriptCard` 不再针对 `executable` 禁用“导出 ZIP”。原生脚本与其他脚本共享预览确认弹窗；原生包的预览文案说明将打包整个脚本目录并列出被排除的内容，不再提示配置 `export.include`。

## 错误处理

- 入口文件缺失、不是普通文件、为符号链接或位于被排除目录时拒绝导出。
- 工作区内任意位置出现符号链接时拒绝导出。
- 工作区没有任何可导出文件时拒绝导出。
- 任一文件或累计文件大小超过 500 MB 时拒绝导出。
- 保存对话框取消时不创建文件且返回空结果。

## 测试

1. 原生导出计划包含整个根目录，未声明 `export.include` 也能带上子目录资源。
2. 原生包纳入源码白名单会拒绝的 `.json`、`.db`、`.xlsx`、`.zip`、`.log` 和 `dist/` 内容。
3. 原生包排除依赖目录、缓存目录、`.env` 系列和凭据文件。
4. 入口缺失或位于被排除目录时拒绝导出。
5. 原生二进制可超过原先的 10 MB 限制，但超过 500 MB 会被拒绝。
6. 原生包忽略 `export.include` 且不因未匹配而报错；工作区内的符号链接仍被拒绝。
7. JavaScript/Python 导出计划继续执行既有静态依赖收集，越界 `export.include` 仍被拒绝。
8. 卡片菜单不再禁用原生脚本的导出操作。
