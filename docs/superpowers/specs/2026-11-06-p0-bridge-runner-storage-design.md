**状态**：设计已确认，待书面审阅

**取代**：`2026-07-11-hub-local-install-design.md` 与 Hub 侧同名规格里，`POST /install` 接受调用方 `zipUrl`、以及 CORS 使用 `*` 的约定

---

## 1. 目标

修四个已经定位到代码的 P0：

1. 任意网页不能再让本机从任意地址下载并导入脚本包。
2. 用户 JS 里的同步死循环不能再卡死整个应用；超时和停止必须能结束这次运行。
3. sql.js 不能再对每次写入同步覆盖 `autoforge.db`；写入中途崩溃不能损坏已有库文件。
4. 环境变量不能再以明文 JSON 留在数据库里。加密可用时自动迁走已有明文。

**非目标**：

- 定时任务的时区、misfire 补偿和防重叠
- JS 权限沙箱（限制文件与网络）
- 更换数据库引擎（`node:sqlite`、`better-sqlite3`）
- 改动 `/auth/callback`
- 把环境变量密文做成可在另一台机器上解开的备份格式

四条改动各自失败时停在自己的边界上，不连带回滚已经完成的另一条。

## 2. Hub 安装契约

网页不再把 `zipUrl` 交给本机桥。应用内安装和网页安装都由桌面端向已配置的 Hub 取包，并核对 SHA-256。

### 2.1 本机桥

| 项 | 值 |
|----|-----|
| 地址 | `http://127.0.0.1:19276` |
| 探测 | `GET /health`，保持可用 |
| 安装 | `POST /install` |
| 授权回调 | `GET /auth/callback`，本次不改 |

`POST /install` 的 JSON 只含两个字段：

- `hubScriptId`：非空字符串
- `installToken`：Hub 现有的一次性安装令牌（TTL 仍为 120 秒，下载时消耗）

请求体里如果出现 `zipUrl` 或 `sha256`，桥返回 `400 invalid_request`，并且不下载。缺少任一必填字段同样返回 `400`。

桌面端用设置中的 Hub 地址拼下载链接：

`{Hub 源}/api/scripts/{hubScriptId}/download?installToken={installToken}`

链接的源（scheme、host、port）必须等于当前配置的 Hub 源。Hub 未配置、地址不是 http/https、或源对不上时，桥拒绝安装。

`Origin` 必须等于当前配置的 Hub 源。缺失或不匹配时拒绝，包括 `Origin: null`。CORS 只在 `Origin` 匹配时回显该源，并允许 `Content-Type`。不再发送 `Access-Control-Allow-Origin: *`。`GET /health` 不要求 `Origin`；只有匹配的源能从浏览器读到响应。

### 2.2 Hub 上的哈希

保存脚本包时计算文件的 SHA-256（十六进制小写），写入脚本记录的 `file_sha256`。`install-token` 的 JSON 增加 `sha256`，值与 `file_sha256` 相同。

下载响应增加 `X-Autoforge-Sha256`，值同样来自 `file_sha256`。旧包该字段为空时，第一次下载按已存文件补算并写回，然后再把字节和响应头发给调用方。直读本地文件和代理存储两条下载路径都带这个响应头。

### 2.3 桌面端核对

桥和应用内安装都这样做：

1. 从 Hub 下载完整 zip 到临时目录。
2. 计算下载内容的 SHA-256。
3. 与响应头 `X-Autoforge-Sha256` 比较。应用内安装还要求它与 `install-token` 返回的 `sha256` 一致。
4. 一致才解压并导入。不一致、响应头缺失，或两处哈希不一致：删除临时下载，不导入，不留下半份脚本包。

网页调用桥时不传哈希。桌面端只相信自己从已配置 Hub 拿到的响应头。

### 2.4 失败

桥在 JSON 里返回 `error` 和中文 `message`。网页继续优先展示 `message`。

| 情况 | HTTP | `error` | `message` |
|------|------|---------|-----------|
| 源不匹配、Hub 未配置、请求体不合法 | 400 | `invalid_request` | 安装请求无效 |
| 令牌无效或过期 | 400 | `invalid_request` | 安装链接无效或已过期 |
| 哈希缺失或不一致 | 400 | `invalid_package` | 脚本包校验失败 |
| 下载失败 | 502 | `download_failed` | 下载失败，请重试 |
| 正在安装 | 409 | `busy` | 正在安装，请稍候 |

## 3. JS 脚本放进 utilityProcess

每次运行 JS 脚本，主进程在依赖安装完成后启动一个 Electron `utilityProcess`。一个会话对应一个子进程。Python 和可执行脚本仍走现有子进程。

子进程加载应用自带的宿主入口，再 `import()` 用户入口并调用 `run`、`main` 或 `default`。启动消息携带 `env`、`params`、`sessionId`、`scriptId`，以及 `paths.userData` 和 `paths.scriptDir`。主进程不再 `import()` 用户代码。

主进程保留会话、日志、阶段、进度和超时计时。子进程用消息送回 `log`、`stage`、`progress`、正常结果和错误。`sdk.browser.launch()` 在子进程内执行。浏览器启动成功后，子进程把浏览器 PID 发给主进程。

`AbortSignal` 不跨进程传递。子进程自己创建 `AbortController`。停止或超时时，主进程先发 `abort`，等待 **1000ms**。子进程若在这 1000ms 内退出，不再强杀。到时仍未退出，或事件循环已经卡死，主进程杀掉该 `utilityProcess`，并结束已经报上来的浏览器 PID。超时计时器留在主进程。

用户点击停止，会话状态为 `stopped`。超时，会话状态为 `error`，错误信息写明超时秒数。子进程崩溃、宿主入口缺失，或用户入口函数不存在时，只把这一次会话标为失败并保留错误信息。停止只影响这一次运行。

本次不限制脚本能访问的文件和网络。

## 4. 数据库落盘

继续使用 sql.js，数据库仍在内存中。改的是何时写盘，以及怎样替换 `autoforge.db`。

事务外的单条 `run` 和 `exec` 只把库标成脏。防抖从最后一次变脏再等 **300ms**；同一批里若写入持续不断，从这批第一次变脏起最晚 **1000ms** 必须刷盘。`transaction()` 在 `COMMIT` 成功后立即落盘，调用方返回时这次事务已经在磁盘上，并清掉等待中的防抖。迁移和启动初始化结束后立即落盘，不走防抖。`close()` 取消等待中的定时器并同步刷盘。应用退出时现有的 `closeDatabase()` 会走到这里。

落盘仍用 `db.export()` 导出整库。字节写入同一目录下的 `autoforge.db.tmp`，`fsync` 后替换 `autoforge.db`。替换完成前不删除、不截断原文件。启动时若发现残留的 `autoforge.db.tmp`，删掉它，不用它打开数据库。替换过程中崩溃，下次仍打开替换前的那一份。

查询和只读 `PRAGMA` 不触发落盘。

## 5. 环境变量加密

只加密 `environments.variables`。名称和描述保持明文。`secret` 继续只做界面掩码。

加密可用时，整段变量 JSON 用 `safeStorage` 加密。库中的文本格式为 `enc:v1:` 加上密文的 Base64。读出时解密。交给界面和脚本运行的仍是原来的 `Record<string, string>`。

已有明文是以 `{` 开头的 JSON。加密可用时，数据库打开并完成迁移后逐条加密并写回。某一条在写回前崩溃，该条保持明文，下次启动继续迁。

解密失败时不更新该行，也不把变量显示成 `{}`。返回给界面的环境对象带 `variablesReadable: false`（该字段不入库）。设置里该环境标为不可读，保存不可用。仓库拒绝这次保存。

`safeStorage` 不可用时，继续按明文读写，重启后环境变量仍在。设置里环境变量区域显示：当前未能加密，变量以明文留在本机数据库。密文绑在这台机器、当前用户的系统密钥上。

## 6. 验证

用现有的 `node --test`。新增测试文件要写进 `package.json` 的 `test:unit`，否则不会跑到。

- 桥拒绝缺失或不匹配的 `Origin`，拒绝带 `zipUrl` 或 `sha256` 的请求体。下载内容与 `X-Autoforge-Sha256` 不一致时不导入，临时文件被删掉。Hub 保存包时写入 `file_sha256`；旧包在第一次下载时补上。
- 宿主协议能传回日志、进度、结果和错误。停止和超时会结束对应子进程。协作式脚本在 1000ms 内退出则不再强杀。
- 300ms 内的多次写入只替换一次库文件。持续写入最晚 1000ms 落盘。事务提交立即落盘。`close()` 刷掉未落盘的改动。残留 `autoforge.db.tmp` 在启动时删除，且不会被当作数据库打开。
- 环境变量能加解密往返。明文 JSON 在加密可用时变成 `enc:v1:`。解密失败不覆盖原值，并拒绝保存。加密不可用时仍以明文保存。
