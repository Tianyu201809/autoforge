# Autoforge v1.24.0 Release Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish complete v1.24.0 documentation for the delivered local MCP integration and keep every current-version index synchronized.

**Architecture:** Add one version-specific release document as the detailed source, summarize it in the changelog, and update README/architecture links to point at the new current version. Reuse `docs/mcp.md` for operational setup details instead of duplicating every client configuration example.

**Tech Stack:** Markdown, Electron/TypeScript project documentation, MCP terminology.

## Global Constraints

- Document application version `1.24.0` and keep script specification version `autoforge 1.0` unchanged.
- Describe only delivered MCP tools, resources, local transports, confirmation rules, token handling, Codex configuration, structured-result compatibility, and adapter reconnection.
- Keep Prompts, dependency installation, categorization, scheduling, window control, and arbitrary shell explicitly outside this release scope.
- Follow the headings, summary table, module table, related-document table, and concise Chinese prose used by existing version documents.
- Do not change runtime code or dependencies.
